# Accessibility

- `specs/a11y.spec.ts` with `support/axe.ts` (`@axe-core/playwright`, pinned, dev dependency only): `expectAccessible(page, { include?, skip?, exclude? })` runs axe (WCAG 2.0/2.1 A/AA and best-practice tags) and fails with rule id, impact, help URL and selectors.
  - `include` checks only the named parts (`DIALOG` = every open `[role="dialog"]`); axe runs the page-level rules (landmarks, one h1, title) only on a whole page.
- One test per page or dialog; it waits for the page's own content and `settled(page)` (the h1 and every image loaded) before the check, so a failure names the page.
- A new page, route or dialog gets its test there at both viewports (a phone- or desktop-only one skips the other with the reason), in English only: axe's rules do not depend on the language.
- The `in <locale>` block keeps three tests per other language: the guest walk (Explore, a combination, a glaze, and `<html lang>`), the feedback dialog with a photo, the Administration landing; the footer test runs in every language. Never add a page there.
- What a translation can break in a name is unit-tested in every language instead: `lib/i18n/accessible-names.test.ts` (each key in a naming attribute or prop exists, is not blank and parses), `i18n.test.ts` (ICU arguments as in English, visible text inside the `aria-label`, `<html lang>`); long words: `overflow.spec.ts`.
- Data: the library (two potters, nine glazes, five combinations, the first two with photos) is a worker-scoped fixture, `seedLibrary(newApi, naming, photos)`, which answers the IDs. A test seeds anything else through `Api`; states the API cannot produce (site admin, changed terms, the offline icon, a mail-sending server) come from `mockApi`.
- Never disable a rule for the whole suite. An unavoidable false positive is one `skip` (rule id) or `exclude` (selector) entry on the one check, with a `reason` string saying why the app cannot satisfy it there; none exists today.
- Fix a violation in the app, in this order: accessible name = visible text (`label-content-name-mismatch`: an `aria-label` starts with the visible text in every language), landmarks, heading order, ARIA, contrast tokens (`lib/layout/contrast.test.ts`).
- `incomplete` results are only annotated (`axe-needs-review` in the report): symbol-only glyphs and text over photos.
- Not covered: the shelf scan sheet's decoded-code state (no axe case; `barcodeVideo` can film the code) and screen-reader behaviour.
