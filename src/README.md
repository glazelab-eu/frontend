# Frontend source map

Files are grouped by the feature that owns them. Keep the layers separate: a page owns drafts and submission state, components receive typed data and callbacks, state modules coordinate lifetimes and requests, and `lib` contains domain rules and browser adapters. Tests stay beside the module they exercise.

| Folder                                                                                  | Responsibility                                                                                                                                                                                                                                                                                  |
| --------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pages/about`                                                                           | The About page (static text)                                                                                                                                                                                                                                                                    |
| `pages/account`                                                                         | Account settings and terms routes                                                                                                                                                                                                                                                               |
| `pages/admin`                                                                           | Administration landing page, moderation queues, bans and error reports                                                                                                                                                                                                                          |
| `pages/catalog`                                                                         | Explore, glaze details and combination details                                                                                                                                                                                                                                                  |
| `pages/clubs`, `pages/stock`, `pages/studio`                                            | Club, shelf and recording routes                                                                                                                                                                                                                                                                |
| `components/ui`                                                                         | Generic UI library (imports only `svelte` and itself): combobox, modal, headings, chips, back link, menu                                                                                                                                                                                        |
| `components/common`                                                                     | Shared pieces that know the app (translated texts): confirm dialog, form error, offline note, refresh hint                                                                                                                                                                                      |
| `components/layout`, `components/routing`                                               | App shell, navigation, install/update notices and route status                                                                                                                                                                                                                                  |
| `components/account`, `components/auth`, `components/legal`                             | Account settings, sign-in/recovery, terms/contact views and the footer's source and licence links                                                                                                                                                                                               |
| `components/avatars`, `components/buddies`, `components/feedback`                       | Profile pictures, buddy relationships/codes/shelf messages and the feedback dialog                                                                                                                                                                                                              |
| `components/explore`, `components/glazes`, `components/combinations`, `components/tags` | Catalog browsing, item forms/cards and tags                                                                                                                                                                                                                                                     |
| `components/catalog`                                                                    | Catalog controls shared by both item types: favourites and the guest invitation                                                                                                                                                                                                                 |
| `components/images`, `components/vision`                                                | Photo display/edit/upload and optional photo suggestions/similar looks                                                                                                                                                                                                                          |
| `components/scanning`, `components/sharing`                                             | Barcode/QR/label scanners and sharing/QR display controls                                                                                                                                                                                                                                       |
| `components/admin`, `components/clubs`, `components/stock`, `components/studio`         | Components owned by those features                                                                                                                                                                                                                                                              |
| `state/app`                                                                             | App state (`app-state.ts`), the controller core (`app-controller.ts`), the module context (`context.ts`), load ticket, snapshot, listing sync, session, load, account data, share and diagnostics wiring, write contract and controller integration tests; shared mock API in `test-helpers.ts` |
| `state/admin`, `state/navigation`                                                       | Admin actions/paged lists and navigation/history coordination                                                                                                                                                                                                                                   |
| `state/stock`, `state/buddies`, `state/account`, `state/feedback`                       | The controller's shelf, buddy, own-account and feedback actions (`*-actions.ts`)                                                                                                                                                                                                                |
| `state/catalog`, `state/clubs`, `state/images`                                          | The controller's catalog, club and photo actions (`*-actions.ts`) beside the feature sessions and rune state                                                                                                                                                                                    |
| `state/legal`, `state/studio`, `state/vision`                                           | Feature sessions, async work and rune state                                                                                                                                                                                                                                                     |
| `state/shared`                                                                          | Component lifetime and confirmation helpers                                                                                                                                                                                                                                                     |
| `lib/<feature>`                                                                         | Domain rules and browser/storage adapters; profile-picture helpers in `avatars`, moderation rules in `admin`                                                                                                                                                                                    |
| `lib/api`, `lib/generated`                                                              | Typed API boundary and generated SDK; generated files are never edited by hand                                                                                                                                                                                                                  |
| `test`                                                                                  | Shared typed fixtures and checks that span multiple component features                                                                                                                                                                                                                          |

Use direct imports. Do not leave forwarding files at old paths or add barrel modules merely to shorten imports. Keep the existing one-level component folders; a new folder should represent a distinct responsibility, not a component's size. A feature can have a page, components, state and pure helpers without merging those layers.

Routing still enters through `App.svelte`; `boot.ts` remains the first import of `main.ts`. The rules, contracts and commands are in `../AGENTS.md` and the topic files under `../docs/guide/` that its index names.
